# Syrka Calendar and Forms

Native feature branch: `feature/calendar-forms`, stacked on verified Sessions baseline `d87142c`. Sessions draft PR stays unmerged. Routes live under the existing Next.js `/workspace` basePath; no separate app/project or production route change.

## Implemented

Calendar: first-class desktop/mobile navigation; account cloud persistence and explicit local demo; month/week/day/agenda; date navigation, mini month, search and calendar filtering; multiple named/coloured calendars, default selection and owner-managed account-ID sharing; event CRUD, time/duration editing, drag date rescheduling, categories, attendees, visibility, locations and legitimate meeting links. Daily/weekly/monthly custom intervals/weekdays/end count/end date, one-occurrence overrides/cancellation, whole-series edits, Prague DST handling, overlap indicators, static ICS import and standards-aware ICS export with VTIMEZONE. Server-scheduled in-app reminder jobs and inbox; signed daily refill/cleanup worker. Local free-slot suggestions and optional consented Qwen proposals, each reviewed before saving. Manual versioned integration proposal inbox with idempotency and approve/reject.

Forms: first-class library/search/sort/draft/published/closed/archive/soft-delete/restore; three editable templates; rename/duplicate; question insertion, type changes, order, duplication/deletion, descriptions, sections, validation, required fields, branching with cycle/forward-reference rejection, preview, undo/redo, debounced optimistic-concurrency autosave and interrupted-session recovery. Published schemas are immutable. Public/authenticated forms, response limits, closing dates, authenticated one-response mode, confirmation/receipt, public link and QR PNG. Public mobile respondent page has no Workspace account requirement. Supported controls: short/long text, single/multiple choice, dropdown, checkboxes, yes/no, number, email, website, date/time/date-time, rating/linear scale, Likert, radio/checkbox grids, ranking, consent, acknowledgement, information and sections; private size/type-limited file upload. Practice scoring for configured single choice/dropdown/yes-no/number answers, not official grades. Owner response review/delete, actual counts and question distributions/numeric averages, answer search, 25-row review pages, selected-version CSV/XLSX exports and a new editable Tables snapshot. Optional consented Qwen editable draft creation; never automatic publication.

Appearance: refined Syrka SVG branding, rounded panels, restrained accents, visible sun/moon toggle, persistent scoped light/dark theme before first paint, touch controls, reduced-motion support. Existing Workspace and Sessions appearance remains scoped separately.

## Explicit limitations / remaining product scope

This is a functional initial release, **not the entire master roadmap completed**. No Google/Outlook OAuth sync, CalDAV subscriptions, live Campus/Mail/Passport/Roadmaps/Dashboard integrations, automatic Sessions room creation/metadata linkage, institutional grades or trusted automation rules. Only versioned contracts, manual CalendarAction proposals, existing meeting links and static ICS are active. ICS imports reject unsupported rules/exceptions rather than losing them; duplicate UID imports into a calendar are skipped. ICS export emits explicit timezone transitions through at least 15 years; indefinite events beyond that horizon require re-export/current IANA-aware consumers. “This and future” recurrence edits, graphical duration resizing and drag-to-create are not implemented; edit dialogs provide keyboard/touch alternatives.

Forms do not yet implement organisational ownership/restrictions, invite-only permissions, shared editor/reviewer roles, editable submissions/email receipts, safe embedding, image blocks, calculated fields, manual grading, timed/attempt-limited quizzes, grade transfer, AI rewriting/translation/thematic response analysis or a live read-only Tables link/refresh. Acknowledgement is not a legal electronic signature. Templates contain no fabricated research. There is no completion-rate statistic because respondent sessions are not tracked. Response analysis currently loads up to 10,000 latest rows in 500-row batches and paginates the review UI; a visible warning bounds analytics/exports above that limit. A dedicated aggregate/paginated analytics service is needed before large institutional deployments. Malware scanning is a declared integration point, not an active scanner. Scheduled reminders are in-app only; no OS push/email promise.

## Development and deployment

1. Use the existing repository, install with `npm ci`, and copy `.env.example` to private local configuration. Existing dedicated Supabase URL/publishable key stay unchanged.
2. Review/apply the six additive `native_*` migrations to the intended **Workspace** project. The hosted target was reviewed and local RLS/crypto tests passed before application; never apply to Campus/Roadmaps.
3. Generate a random 48-byte server signing key, put it in Vercel Preview `SYRKA_NATIVE_SIGNING_KEY` for this branch and provision the matching private `native_private.keys` v1 row through an authorized operator. Never commit it or use a NEXT_PUBLIC name. No service-role key is required by app code.
4. Existing Workspace general-purpose Qwen secrets remain server-only. Preview integration flags/LiveKit credentials were made inheritable across Preview branches **without changing their values or production targets**, preserving `LIVEKIT_DEVELOPMENT_ONLY=true`. Provider Free Quota Only must remain verified. AI is optional.
5. Commit/push the feature branch. Vercel Git integration builds the existing `syrka-workspace` project automatically. Use a separate Calendar/Forms Preview alias; preserve `syrka-workspace-preview.vercel.app` for Sessions QA and all production domains.
6. Point the private worker configuration at the Calendar/Forms Preview alias's `/workspace/api/native/worker`; verify actual cron delivery and refill HTTP status. Inspect `docs/native/security.md` before release.
7. Run `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run test:e2e`. See the release report for observed results and screenshot evidence. Never merge/promote without acceptance and approval.

`node scripts/verify-native-preview.mjs` is an opt-in real-service acceptance runner requiring isolated operator-provisioned QA actors in a private file. Set `SYRKA_PREVIEW_URL`, `SYRKA_QA_ACTORS_FILE`, and optionally `SYRKA_TEST_AI=true`. It authenticates two real test users, writes synthetic records through RLS/API, submits anonymously, uploads a private file, reopens an actual XLSX, opens a Tables snapshot and captures mobile/desktop evidence. It must not be run against real user records. Remove its QA rows/users and private fixture after use. It never prints keys, passwords or user speech.
